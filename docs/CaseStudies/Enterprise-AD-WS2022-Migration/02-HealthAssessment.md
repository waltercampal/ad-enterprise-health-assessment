## Findings that block or complicate the migration

These are pulled out because they must be resolved (or explicitly
risk-accepted) before Phase 1 of the [Migration Plan](03-MigrationPlan.md)
starts:

| # | Finding | Category | Severity | Target |
|---|---------|----------|----------|--------|
| 1 | Replication failing (error 1722, RPC unavailable) | Replication | High | DCBR23 |
| 2 | DNS Service unreachable / stale LDAP SRV record | DNS | High | DCBR23 |
| 3 | SYSVOL share unreachable | SYSVOL | High | DCBR23 |
| 4 | FRS migration state is "Prepared", not "Eliminated" | SYSVOL | High | branches.fabrikam.com |
| 5 | SMBv1 protocol still enabled | Security | High | DCBR22 |
| 6 | Kerberos pre-authentication disabled on a Domain Admins account (AS-REP roasting) | Security | High | svc-legacy-backup |
| 7 | System drive at 6% free space | ServerConfig | High | DCTRE20 |
| 8 | ADCS (Enterprise CA) co-located on a Domain Controller | MigrationReadiness | Medium | DCTRE20 |
| 9 | LAPS not deployed at the forest level | Security | Medium | Forest |
| 10 | GPO SYSVOL/AD version mismatch | Group Policy | Medium | Branch Printer Deployment (branches.fabrikam.com) |

Findings #1-#3 are all on the same Domain Controller (DCBR23) and point to a
single root cause: a network/firewall path issue between Branch-North-02 and
Hub-Central, not an Active Directory fault. This is the top remediation
priority - see [Migration Plan &sect;1](03-MigrationPlan.md#1-pre-migration-remediation-blocking).

## Positive findings worth preserving

- Forest and all 4 domains are already at the Windows Server 2016 functional
  level - no functional level raise is required before introducing 2022 DCs.
- No Windows Server 2008/2008 R2 Domain Controllers anywhere in the forest -
  the hardest migration blocker is already absent.
- 3 of 4 domains have completed the FRS to DFSR SYSVOL migration.
- Kerberos and time synchronization are healthy everywhere except the one
  already-flagged branch DC.
